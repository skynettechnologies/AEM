# All in One Accessibility® Pro – Adobe Experience Manager app

This AI-powered website accessibility app improves usability for people with visual, auditory, motor, and cognitive disabilities. It offers **100+ accessibility features**, **190+ languages**, and **12 accessibility profiles**.

This app helps Adobe Experience Manager websites improve accessibility for **51+ global standards**, including WCAG 2.0, 2.1, 2.2, ATAG, ADA, EAA, Section 508, France RGAA, California Unruh, European EAA EN 301 549, UK Equality Act, Spain UNE 139803:2012, Australian DDA, Israeli Standard 5568, UAE Disability Act (Federal Law No. 29 of 2006), Saudi Web Accessibility Standards, Qatar National e-Accessibility Policy, Ontario AODA, Canada ACA, German BITV, Brazilian Inclusion Law (LBI 13.146/2015), JIS X 8341 (Japan), Italian Stanca Act, Indian RPwD Act, Switzerland DDA, and other [accessibility standards](https://www.skynettechnologies.com/accessibility-standards).

The [website accessibility app](https://www.skynettechnologies.com/all-in-one-accessibility) creates a strong foundation for digital compliance on Adobe Experience Manager websites.

## Installation

Download `all-in-one-accessibility.zip` from the [latest release](https://github.com/skynettechnologies/AEM/releases).

### AEM as a Cloud Service

On AEM as a Cloud Service, code is deployed through Cloud Manager (Package Manager cannot install code there). Add the package to your AEM project once:

1. Copy `all-in-one-accessibility.zip` into your project's `all` module:
   `all/src/main/content/jcr_root/apps/<your-project>-vendor-packages/container/install/`
2. Make sure `all/src/main/content/META-INF/vault/filter.xml` contains:
   ```xml
   <filter root="/apps/<your-project>-vendor-packages"/>
   ```
3. Commit, push to your Cloud Manager Git repository, and run the deployment pipeline.

### Local AEM SDK (development and testing)

1. In AEM, go to **Tools → Deployment → Packages** (on author and on publish).
2. Click **Upload Package**, choose `all-in-one-accessibility.zip`, select **Force Upload**, and click **Install**.

### After installation

1. **The widget is added to your site automatically**: every page under `/content` gets it, with no template or page changes. Flush the Dispatcher / CDN cache once after the deployment.
2. Open **Tools → All in One Accessibility → Widget Settings**. Your website domain is detected automatically, and the free widget is registered for it.
3. Select your All in One Accessibility plan, or start the 10-day free trial with **Upgrade to Paid Plan** (the trial form is pre-filled with your website and AEM user details).
4. Open a published page and verify that the All in One Accessibility widget appears (bottom right, after about 3 seconds). Press **Ctrl + Shift + A** to open it.

For a detailed walkthrough, see the [Adobe Experience Manager accessibility app installation guide](https://www.skynettechnologies.com/blog/adobe-experience-manager-web-accessibility-widget-installation).
Need help? Our support team can assist with the integration if you don't have a development team.

## Configuration

Configure the widget inside AEM:

1. Go to **Tools → All in One Accessibility → Widget Settings**.
2. Choose the widget color, icon type, icon size, widget size and position (preset or exact position in pixels).
3. Click **Save Changes**. The widget on your website updates within a few seconds.

Paid plans also unlock the **Paid Features** and **Accessibility Score** tabs, and a **Dashboard** button that opens the accessibility dashboard.

### Optional AEM settings

OSGi configuration **All in One Accessibility - Settings** (on AEM as a Cloud Service, set the environment variables in Cloud Manager):

| Setting | Environment variable | Purpose |
|---|---|---|
| Site domains | `AIOA_SITE_DOMAIN` | Your public website domain, if it is not detected automatically |
| Company name | `AIOA_COMPANY_NAME` | Sent with the registration and the trial form |
| Add widget to pages automatically | – | On by default; turn off to place the widget component manually |
| Automatic: include / excluded paths | – | Limit the widget to certain sites, e.g. `/content/mysite` |
| Widget enabled | – | Master switch for the widget |
| Allowed groups | – | Who may open Widget Settings (default: `administrators`) |

Advanced settings (accessibility statement link, alt-text editing, team management, analytics) are managed from the [accessibility dashboard](https://ada.skynettechnologies.us/front/login).

## CORS Policy Configuration

To avoid CORS policy issues, ensure the following URLs are allowed on your website. Add them to your CORS configuration or trusted domains list.

| **Domain** | **Description** | **Usage** |
| --- | --- | --- |
| https://\*.skynettechnologies.com | Skynet Technologies (Global Domain) | API access and resources |
| https://\*.skynettechnologies.us | Skynet Technologies (US Domain) | API access and resources |
| https://\*.googleapis.com | Google APIs | Services like Fonts, Translation |
| https://\*.gstatic.com | Fonts APIs | Custom Fonts |
| https://vlibras.gov.br | VLibras – Brazilian Sign Language Service | Sign Language |
| https://ipapi.co | ipapi – IP Geolocation API | Called once during installation to detect an EU location and add the EU-based app script (endpoint: `/json/`) |

**Instructions**

1. Update your server's CORS configuration to include these URLs.
2. Ensure wildcard subdomains (\*) are supported where necessary.
3. Verify functionality by testing requests to these domains.
4. If issues persist, consult the documentation for CORS configuration guidance.

## FAQs

**Is this app compatible with multisite setups?**

Yes. Each domain and subdomain needs its own license, or you can choose a multisite plan to manage several websites from one dashboard.

**Are any features limited in the free trial?**

No. The 10-day free trial includes all accessibility features.

**Does it support multilingual websites?**

Yes. It supports 190+ languages and automatically detects the visitor's browser language. If your site's default language is, for example, Spanish, the screen reader will read in Spanish.

**Which languages do the screen reader, virtual keyboard, and other features support?**

Screen Reader, Talk & Type, and Live Site Translation support 50+ languages; the Virtual Keyboard supports 40+ languages; Voice Navigation and Dictionary Search support 15+ languages. [See language support details](https://www.skynettechnologies.com/all-in-one-accessibility/languages).

**Can I change the screen reader voice?**

Yes. You can choose from a range of voices by tone, accent, and speech style.

**Does it handle image alt text?**

Yes. AI automatically remediates image alt text, and you can add or edit alt text from the dashboard.

**Can I change the accessibility statement?**

Yes. Set a custom accessibility statement URL from the dashboard under app settings.

**Does it include sign language?**

Yes. It includes Brazilian Sign Language (Libras).

**Will it slow down my website?**

No. The app loads asynchronously and typically adds under 100 ms, with negligible impact on page speed.

**Do staging or development sites need a separate license?**

No. After purchase, contact [hello@skynettechnologies.com](mailto:hello@skynettechnologies.com) with your staging/UAT URL and it will be added free of charge.

**Can I remove Skynet Technologies branding?**

Yes, with the White Label add-on.

**Can I customize the accessibility menu?**

Yes. The Modify Accessibility Menu add-on lets you reorder, remove, and restructure menu items and languages.

**Is there a discount for non-profits or multiple websites?**

Yes. Discounts are available for 501(c)(3) non-profits and for multiple websites. See [pricing](https://www.skynettechnologies.com/all-in-one-accessibility#scroll-here) or contact us for a custom plan.

**Is on-premises deployment available?**

Yes. Contact [hello@skynettechnologies.com](mailto:hello@skynettechnologies.com) for on-premises pricing and setup assistance.

**Which AEM templates and components are supported?**

The app works across AEM templates, components, and published pages, on both on-premises AEM and AEM as a Cloud Service.
